Pact: контракт пишет клиент, а проверяется сервер

Pact: the client writes the contract, the server is checked against it

Клиент «Pet Adoption Web» в тестах записывает, какие запросы он шлёт и какие поля читает. Получается файл-контракт. Затем этот файл проигрывается против настоящего Petstore. Если сервер перестал отдавать то, на что опирается клиент, проверка поставщика падает до деплоя.

In its tests the "Pet Adoption Web" client records which requests it sends and which fields it reads. That becomes a contract file, which is then replayed against the real Petstore. If the server stops returning what the client relies on, provider verification fails before deploy.

Pact проверяет только то, что клиент действительно использует. Поэтому одни изменения поставщика безопасны, а другие ломают конкретного клиента. Выберите изменение.

Pact checks only what the client actually uses, so some provider changes are safe and others break this particular client. Pick a change.

Pact Broker и can-i-deploy

Pact Broker and can-i-deploy

Здесь клиент и поставщик живут в одном репозитории, поэтому pact-файл передаётся через папку. В реальной компании это разные команды и репозитории: клиент публикует контракт в Pact Broker (или PactFlow), сборка поставщика забирает его оттуда, а перед деплоем команда can-i-deploy проверяет, совместимы ли версии в нужном окружении. У нас этого пока нет — это следующий шаг.

Here consumer and provider live in one repository, so the pact file travels through a folder. In a real company they are separate teams and repositories: the consumer publishes the contract to a Pact Broker (or PactFlow), the provider build fetches it from there, and before deploy can-i-deploy checks that the versions are compatible in the target environment. We do not have that yet; it is the next step.

Дрейф контракта: oasdiff сравнивает две версии API

Contract drift: oasdiff compares two versions of an API

У нас есть утверждённая спецификация Petstore — договор с клиентами. oasdiff сравнивает её с тем, что сервер отдаёт на самом деле, и сортирует каждое отличие: сломает ли оно существующих клиентов. Если сломает и это не принятое расхождение, ночная сборка красная.

We keep an approved Petstore spec: the agreement with clients. oasdiff compares it with what the server actually serves and sorts every difference by one question: will it break existing clients? If it will, and it is not accepted drift, the nightly build fails.

oasdiff
breaking

Главная идеяThe key idea

Что ломает клиента, а что нет

What breaks a client and what does not

Всё зависит от направления данных. Запрос пишет клиент, ответ читает клиент. Сервер может стать мягче к тому, что получает, и щедрее в том, что отдаёт, но не наоборот.

It depends on which way the data flows. The client writes the request and reads the response. A server may become more lenient about what it accepts and more generous in what it returns, never the reverse.

Почему CD-1 принят, а не исправлен
Why CD-1 is accepted, not fixed

        
Образ swaggerapi/petstore3:unstable отдаёт спецификацию 1.0.17, а утверждённый контракт — 1.0.29-SNAPSHOT из master. В старой версии у 7 операций нет ответа 200. Это чужая система, исправить её мы не можем, но обязаны это видеть.

        
The swaggerapi/petstore3:unstable image serves spec 1.0.17, while the approved contract is 1.0.29-SNAPSHOT from master. The old version has no 200 response on 7 operations. Not our system to fix, but we must see it.

        
Каждая строка — метод, путь и описание изменения из вывода oasdiff. Новое ломающее изменение, которого нет в файле, сразу даёт красную сборку.

        
Each line is a method, a path and the change text from oasdiff output. A new breaking change not in the file turns the build red at once.

        
Перекрёстная проверка: Schemathesis независимо нашёл то же самое как FZ-2 — сервер возвращает 200 на DELETE, которого нет в его спецификации.

        
Cross-check: Schemathesis found the same independently as FZ-2: the server answers 200 on DELETE, which its spec does not list.
